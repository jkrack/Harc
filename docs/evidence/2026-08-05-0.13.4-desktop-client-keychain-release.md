# Harc 0.13.4 Desktop Client Keychain release

**Date:** 2026-08-05

**Source commit:** `9fdf540` (`Fix Desktop Client Keychain bootstrap`)

## Observed production failure

On a clean secondary Mac running Harc 0.13.3 (48) in Client mode, both the
Library and Pair with Host flow failed during application bootstrap with
`HarcIdentity.InstallationKeychainError error 0.` Read-only inspection found:

- no `com.harc.Harc.desktop-client.installation-identity` Keychain item;
- no files under `~/Library/Application Support/Harc/ClientState`;
- no Client captures; and
- a stable notarized Developer ID requirement for bundle `com.harc.Harc` and
  Team ID `63TNU5M7P4`.

This proves the failure happened before identity or Client state creation, so
the affected Mac does not require destructive cleanup or migration.

## Root cause and correction

The shared software identity store unconditionally selected the Data
Protection Keychain. That domain requires an entitlement unavailable to Harc's
non-sandboxed Developer ID macOS app, causing Security.framework to return
`errSecMissingEntitlement` during first Client startup.

Harc 0.13.4 selects the local, non-synchronizing legacy login Keychain for the
macOS Desktop Client and `harcctl`, while the iOS app explicitly retains the
Data Protection Keychain. The release also:

- exposes actionable Keychain OSStatus descriptions;
- reports the actual runtime startup error from the Library alert;
- publishes Client runtime readiness in Settings; and
- provides a visible **Pair with Host…** action when the Client is ready.

## Remaining physical acceptance

After the secondary Mac updates to 0.13.4, it must create its first identity,
show **Client is ready**, pair with the Host, preserve its separate On This Mac
library, locally process one capture, and upload the signed result for visible
Host acceptance or reprocessing. This release removes the bootstrap blocker;
it does not claim that physical PR 9 acceptance is complete.
