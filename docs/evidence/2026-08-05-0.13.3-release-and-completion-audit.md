# Harc 0.13.3 release and completion audit

**Date:** 2026-08-05

**Normative specification:** [2026-08-02 Host/client/mobile implementation specification](../specs/2026-08-02-host-client-mobile-implementation-spec.md)

## Decision

The current source and macOS distribution gates are green. Harc 0.13.3 (48)
is published through Sparkle and GitHub from the pushed `main` branch. The
release contains the 0.13.2 secure desktop-pairing, paired-device identity,
iPhone camera-preview, mobile capture-queue, and Library timestamp fixes plus a
version-integrity correction and deterministic daemon regression isolation.

This audit does **not** claim the full host/client/mobile objective complete.
The production mobile codec gate remains deliberately closed, the post-fix
physical iPhone capture/transfer matrix is not green, and a real secondary Mac
has not yet completed the PR 9 acceptance flow against this release.

The first full reruns exposed two real release-gate defects before this
candidate was cut:

1. The 0.13.2 marketing version had advanced while the bundle-less helper/CLI
   fallback remained 0.13.1. Version 0.13.3 advances both under the existing
   drift test rather than replacing already-published 0.13.2 bytes.
2. `DaemonIdleClockTests` launched detached real Core ML preloads even though it
   exercised only the Unix socket and idle clock. The daemon now has a
   production-default model-preload switch; that socket-only test disables it,
   while every shipping call site retains eager preload behavior.

## Physical codec gate

The shipping mobile transfer switch remains fail-closed. No raw-audio fallback
is enabled.

- The iPhone 15 Pro Max (`iPhone16,2`) quick diagnostic proved CAF+ALAC and
  FLAC both execute bit-exactly.
- Its three-hour CAF+ALAC run completed all 180 chunks and passed integrity,
  latency, queue, and memory limits, but failed because serious thermal state
  was observed.
- There is no qualifying FLAC three-hour report and no four-cell oldest/current
  device matrix. Therefore `HARC_MOBILE_QUALIFIED_CAF_ALAC` remains disabled.

The next physical work should be short functional qualification first: update
both Macs to 0.13.3, complete one Mac-to-Mac pairing/record/upload path, then
complete one post-fix iPhone record/stop/local-playback path. Do not begin
another three-hour codec run until the ordinary product flow is stable and a
second named test iPhone is available.
