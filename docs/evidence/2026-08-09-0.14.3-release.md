Harc 0.14.3 build 58 is the published macOS pairing-reliability release. It
fixes two failures observed during a real Mac-client-to-Mac-Host attempt:

- the route selector previously treated construction of a gRPC owner as a
  successful direct connection, even though DNS, TLS, HTTP/2, and trust are
  first exercised by an RPC; a failed first RPC therefore occurred outside
  the relay fallback boundary; and
- the ephemeral relay URLSession imposed a 30-second total resource timeout
  on upgraded WebSockets, which disconnected a healthy Host control socket at
  approximately 30 seconds despite a successful HTTP 101 upgrade.

Route selection now requires an authenticated, idempotent Host-info response
before choosing either the direct or encrypted-relay path. The relay resource
window is 24 hours, with the existing Host-agent reconnection behavior
remaining the bounded lifecycle. Pairing errors distinguish failure before
Host authentication from failure while creating the one-time claim, without
showing invitation capabilities or raw transport identifiers.

## Decision boundary

This closes publication of the macOS 0.14.3 artifact. It does not by itself
prove the original two-Mac scenario: both Macs must install 0.14.3, create a
fresh Mac-client invitation, and complete the security-word and Host-approval
flow. Two-network pairing, post-adoption reconnect, transfer, and revocation
remain physical acceptance evidence rather than claims made from the build.
