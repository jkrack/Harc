# Harc Scaffold Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Create a working macOS project skeleton for Harc with two targets — the `Harc` menu bar app and the `harc-stt` daemon — built via SwiftPM + xcodegen, with shared IPC protocol types, tests, CI, and a signed `.app` bundle that embeds the daemon binary.

**Architecture:** Single repo. A SwiftPM package at the root owns a `HarcCore` library (IPC types, version) and a `harc-stt` executable; `swift test` exercises them. An `xcodegen`-generated `Harc.xcodeproj` builds the menu bar app target, which depends on the SwiftPM package and runs a build script that compiles `harc-stt` in release mode and copies it into `Harc.app/Contents/MacOS/harc-stt`. The menu bar app is intentionally a stub in Plan 1 — just an `NSStatusItem` with a "Quit" menu. Real UI comes in Plan 5.

**Tech Stack:** Swift 6.0, SwiftPM, Swift Testing (`import Testing`), xcodegen, SwiftUI + AppKit (menu bar via `NSApplicationDelegateAdaptor`), GitHub Actions on `macos-15`. Xcode 15.4+ assumed.

Responsibilities:

- `HarcCore` — IPC request/response types, version string. Pure value types, Foundation only. No AppKit, no audio, no side effects. Must be platform-neutral enough that both the daemon and the app import it without dragging in UI dependencies.

- `HarcApp` — menu bar app target. Plan 1 is `NSStatusItem` with "Quit Harc". Popover UI, hotkey, recording lifecycle — all come in Plan 5.
- `scripts/build-daemon.sh` — builds `harc-stt` in release mode into an isolated scratch directory, copies it into `Harc.app/Contents/MacOS/`, and re-signs it. Invoked by an Xcode Run Script build phase.

- [ ] **Step 3: Write `Sources/HarcCore/IPCRequest.swift`**

```swift
import Foundation

public enum IPCRequest: Codable, Equatable {
    case transcribe(TranscribeRequest)
    case status
    case shutdown

    private enum CodingKeys: String, CodingKey { case type, payload }
    private enum Kind: String, Codable { case transcribe, status, shutdown }

    public init(from decoder: Decoder) throws {
        let c = try decoder.container(keyedBy: CodingKeys.self)
        switch try c.decode(Kind.self, forKey: .type) {
        case .transcribe:
            self = .transcribe(try c.decode(TranscribeRequest.self, forKey: .payload))
        case .status:
            self = .status
        case .shutdown:
            self = .shutdown
        }
    }

    public func encode(to encoder: Encoder) throws {
        var c = encoder.container(keyedBy: CodingKeys.self)
        switch self {
        case .transcribe(let r):
            try c.encode(Kind.transcribe, forKey: .type)
            try c.encode(r, forKey: .payload)
        case .status:
            try c.encode(Kind.status, forKey: .type)
        case .shutdown:
            try c.encode(Kind.shutdown, forKey: .type)
        }
    }
}

public struct TranscribeRequest: Codable, Equatable {
    public var audioPath: String
    public var language: String
    public var wantTimestamps: Bool
    public var diarize: Bool

    public init(
        audioPath: String,
        language: String = "en",
        wantTimestamps: Bool = true,
        diarize: Bool = true
    ) {
        self.audioPath = audioPath
        self.language = language
        self.wantTimestamps = wantTimestamps
        self.diarize = diarize
    }

    private enum CodingKeys: String, CodingKey {
        case audioPath, language, wantTimestamps, diarize
    }

    public init(from decoder: Decoder) throws {
        let c = try decoder.container(keyedBy: CodingKeys.self)
        self.audioPath = try c.decode(String.self, forKey: .audioPath)
        self.language = try c.decodeIfPresent(String.self, forKey: .language) ?? "en"
        self.wantTimestamps = try c.decodeIfPresent(Bool.self, forKey: .wantTimestamps) ?? true
        self.diarize = try c.decodeIfPresent(Bool.self, forKey: .diarize) ?? true
    }
}
```

The custom `init(from:)` makes Swift-side defaults the wire defaults too: a minimal `{"audioPath": "/x.wav"}` decodes cleanly with `language="en"`, `wantTimestamps=true`, `diarize=true`. Without this, the Swift init default and the JSON decoder disagree — Plan 2's daemon would reject every request that relied on a default. `encode(to:)` is still compiler-synthesized because only `init(from:)` is customized.

- [ ] **Step 4: Write `Sources/HarcCore/IPCResponse.swift`**

```swift
import Foundation

public enum IPCResponse: Codable, Equatable {
    case result(TranscribeResult)
    case status(DaemonStatus)
    case error(IPCError)

    private enum CodingKeys: String, CodingKey { case type, payload }
    private enum Kind: String, Codable { case result, status, error }

    public init(from decoder: Decoder) throws {
        let c = try decoder.container(keyedBy: CodingKeys.self)
        switch try c.decode(Kind.self, forKey: .type) {
        case .result:
            self = .result(try c.decode(TranscribeResult.self, forKey: .payload))
        case .status:
            self = .status(try c.decode(DaemonStatus.self, forKey: .payload))
        case .error:
            self = .error(try c.decode(IPCError.self, forKey: .payload))
        }
    }

    public func encode(to encoder: Encoder) throws {
        var c = encoder.container(keyedBy: CodingKeys.self)
        switch self {
        case .result(let r):
            try c.encode(Kind.result, forKey: .type)
            try c.encode(r, forKey: .payload)
        case .status(let s):
            try c.encode(Kind.status, forKey: .type)
            try c.encode(s, forKey: .payload)
        case .error(let e):
            try c.encode(Kind.error, forKey: .type)
            try c.encode(e, forKey: .payload)
        }
    }
}

public struct TranscribeResult: Codable, Equatable {
    public var text: String
    public var words: [Word]
    public var speakers: [SpeakerSegment]
    public var processingMs: Int

    public init(text: String, words: [Word], speakers: [SpeakerSegment], processingMs: Int) {
        self.text = text
        self.words = words
        self.speakers = speakers
        self.processingMs = processingMs
    }
}

public struct Word: Codable, Equatable {
    public var text: String
    public var startMs: Int
    public var endMs: Int
    public init(text: String, startMs: Int, endMs: Int) {
        self.text = text
        self.startMs = startMs
        self.endMs = endMs
    }
}

public struct SpeakerSegment: Codable, Equatable {
    public var speaker: Int
    public var startMs: Int
    public var endMs: Int
    public init(speaker: Int, startMs: Int, endMs: Int) {
        self.speaker = speaker
        self.startMs = startMs
        self.endMs = endMs
    }
}

public struct DaemonStatus: Codable, Equatable {
    public var version: String
    public var modelLoaded: Bool
    public var uptimeSeconds: Int
    public init(version: String, modelLoaded: Bool, uptimeSeconds: Int) {
        self.version = version
        self.modelLoaded = modelLoaded
        self.uptimeSeconds = uptimeSeconds
    }
}

public struct IPCError: Codable, Equatable, Error {
    public var code: String
    public var message: String
    public init(code: String, message: String) {
        self.code = code
        self.message = message
    }
}
```

### Task 7: Embed harc-stt in the app bundle

**Files:**
- Modify: `/Users/jlane/GitHub/Harc/scripts/build-daemon.sh` (overwrite placeholder)

- [ ] **Step 1: Overwrite `scripts/build-daemon.sh` with the real implementation**

```bash
#!/usr/bin/env bash
set -euo pipefail

: "${SRCROOT:?SRCROOT must be set (run from Xcode build phase)}"
: "${BUILT_PRODUCTS_DIR:?BUILT_PRODUCTS_DIR must be set}"
: "${CONTENTS_FOLDER_PATH:?CONTENTS_FOLDER_PATH must be set}"

cd "$SRCROOT"

SCRATCH="$SRCROOT/.build-daemon"
echo "note: building harc-stt into $SCRATCH"

swift build \
  -c release \
  --product harc-stt \
  --scratch-path "$SCRATCH" \
  --arch arm64

DAEMON_SRC="$SCRATCH/arm64-apple-macosx/release/harc-stt"
DAEMON_DST="$BUILT_PRODUCTS_DIR/$CONTENTS_FOLDER_PATH/MacOS/harc-stt"

mkdir -p "$(dirname "$DAEMON_DST")"
cp "$DAEMON_SRC" "$DAEMON_DST"

IDENTITY="${EXPANDED_CODE_SIGN_IDENTITY:-}"
if [[ -z "$IDENTITY" ]]; then IDENTITY="-"; fi

echo "note: signing $DAEMON_DST with identity '$IDENTITY'"
codesign --force --sign "$IDENTITY" --options runtime "$DAEMON_DST"

echo "note: embedded harc-stt at $DAEMON_DST"
```

Key decisions:
- **Isolated scratch path** (`--scratch-path "$SRCROOT/.build-daemon"`) keeps nested `swift build` from stomping the top-level `.build` when running inside Xcode.
- **Explicit `--arch arm64`** matches our Apple Silicon constraint.
- **Sign with the same identity Xcode uses** (`EXPANDED_CODE_SIGN_IDENTITY`), falling back to ad-hoc (`-`) when Xcode didn't set one. The outer `Harc.app` sign phase happens after `postCompileScripts`, so the app's final signature will cover the embedded binary.

## Plans 2–6 (one-paragraph sketches)

### Plan 2: `harc-stt` daemon core

Implement the socket server. Listen on `~/.harc/stt.sock`, accept loop, line-delimited JSON codec wrapping `IPCRequest`/`IPCResponse`. Integrate `FluidAudio` as a SwiftPM dependency; pre-load Parakeet TDT 0.6B v3 on daemon start (in a background `Task`); surface `modelLoaded` via `DaemonStatus`. Handle `transcribe(audioPath:)` end-to-end against a short fixture WAV. Add idle-timeout self-shutdown (30 min default) and SIGTERM/SIGINT handling that removes the socket file. **Critical risk spike:** verify a real hour-long audio file transcribes without OOM — if FluidAudio can't handle it natively, add a chunker (60 s windows with 2 s overlap) and a stitch step inside the daemon. Integration test dispatches a real `transcribe` over the socket and asserts word count + non-empty speaker segments. This is the highest-risk subsystem — do it before UI.

### Plan 3: Audio capture + durable WAV

`AVAudioEngine` taps the default input device; `ScreenCaptureKit` (`SCStream` with `audioOnly`) taps system audio. A `RecordingSession` actor mixes both into 16 kHz mono Float32 buffers and streams them through an `AudioFileWriter` to `~/Library/Caches/Harc/recordings/<uuid>.wav` using `AVAudioFile`. `fsync` every few seconds to survive crashes. On stop, atomically move into the user-configured destination folder under `YYYY/YYYY-MM-DD/HH-mm-ss.wav`. Permission handling for microphone + screen recording, including graceful degradation to mic-only when screen recording is denied. Tests: synthetic input → assert WAV header, sample rate, frame count, and that the file opens in QuickTime / `afinfo`.

### Plan 4: Background transcription worker

An `actor` watches the durable WAV and, every ~60 s of recorded audio, hands a chunk to an in-process `HarcSTTClient` that speaks the IPC protocol over the daemon socket. Tracks byte offsets so chunks don't overlap, accumulates `TranscribeResult`s into a session transcript, and stitches diarization/speaker IDs across chunk boundaries. On stop, flushes the final partial chunk, awaits completion, and writes `HH-mm-ss.txt` + `HH-mm-ss.json` alongside the WAV. Exposes an `AsyncStream<TranscriptUpdate>` that the UI subscribes to in Plan 5. Tests: feed a pre-recorded 3-minute file in chunked mode vs whole-file mode and assert the joined transcript matches.

### Plan 5: Menu bar UI (Stitch-driven)

Replace the Task-6 stub with the full SwiftUI popover. Screens to implement, mapped to the Stitch project: **Menu Bar Popover** (primary surface, 780 wide), **Recorder** (large active-session view), **Library** (list of past transcripts with search), **Transcription Detail**, **Settings**. Wire a global hotkey (default pick: `sindresorhus/KeyboardShortcuts`) to toggle recording. The menu bar icon switches between a static `waveform` and an animated red-dot recording indicator. Settings UI surfaces destination folder (security-scoped bookmark if/when sandboxed), hotkey binding, diarization toggle, and auto-paste. Use the Stitch HTML as visual reference, not as emitted code — rebuild in SwiftUI using the design-system tokens from the Stitch `designMd` (Tech-Lavender + Deep Cobalt, glass materials, the "no-line" rule, the ambient-shadow recipes).

### Plan 6: Clipboard history + storage

GRDB + SQLite at `~/Library/Application Support/Harc/Harc.db`. Schema: `recordings(id, started_at, ended_at, wav_path, txt_path, json_path, title, pinned, deleted_at)` with FTS5 virtual table on transcript text. CRUD + full-text search surfaced in the Library view. "Copy" copies the transcript text to `NSPasteboard`; "Paste" uses `CGEvent` keyboard injection into the frontmost app (requires Accessibility permission, gated by a first-run prompt). Renaming, pinning, soft-deletion. "Reveal in Finder" opens the destination-folder hierarchy. Tests: schema migration fixtures, FTS ranking sanity, paste-to-frontmost-app simulated via a helper app target.
